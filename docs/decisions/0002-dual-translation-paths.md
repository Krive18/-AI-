# ADR-0002：运营端提供专业精译与有道智能翻译双路径

## 状态

Accepted

## 日期

2026-09-03

## 背景

内部运营既需要适合正式发布、可分别调优每个环节的高质量翻译，也需要更快、更简单的一体化交付路径。原有流水线把 ASR、文本翻译和 TTS 分配给三个供应商，质量控制能力强，但调用链较长。网易有道的大模型同传可以在一次流式会话中返回源文、译文、时间轴和目标语音，但其首版语言覆盖不含菲律宾语。

无论选择哪条路径，交付成片都必须满足：不保留中文原声，只烧录目标语言字幕，并用 FFmpeg 按时间轴合成目标语言音频，保持视频容器可播放。

## 决策

在项目级保存不可变的 `translation_mode`：

- `professional` 为默认路径，使用豆包 ASR、火山方舟文本翻译和 MiniMax TTS；
- `youdao` 使用有道大模型同传的单 WebSocket 会话取得分段译文、时间轴和语音，再进入统一的 FFmpeg 渲染阶段。

有道能力作为独立供应商能力 `SIMULTANEOUS_INTERPRETATION = 4` 管理。管理员保存 App Key、加密 App Secret、固定官方 WSS 地址和音色参数。运营端在创建项目之前读取真实配置可用性，后端创建项目时再次校验供应商状态与目标语言，防止绕过界面提交不可执行任务。

同一项目选择多个有道目标语言时，Worker 通过项目级 Redis 租约串行执行流式会话，避免并发写入共享源分段。每个语言任务仍独立保存字幕、配音、成片、用量与错误状态，支持单任务重试。

## 备选方案

### 用有道完全替换原流水线

- 优点：调用链更短，供应商配置更少。
- 缺点：菲律宾语暂不支持，各阶段不能独立选型或调优，供应商故障会影响全部能力。
- 结论：保留为可选快捷路径，不替换专业精译。

### 把有道拆成 ASR、翻译和 TTS 三个虚拟供应商

- 优点：表面上复用原有阶段模型。
- 缺点：同传协议本身是一次有状态流式会话，拆分会重复请求并丢失统一时间轴，增加成本和声画漂移风险。
- 结论：使用独立的一体化能力类型。

## 影响

- `translation_project` 新增 `translation_mode`，历史项目自动回填为 `professional`。
- 供应商、价格和用量表的能力约束扩展到 `1..4`。
- 有道路径只允许 `en-US`、`ja-JP`、`ko-KR`、`vi-VN`、`ms-MY`、`th-TH`。
- 有道 App Secret 只保存在后端加密字段中，前端不回显；WSS 地址固定为官方地址，避免管理员配置任意外部主机。
- 有道远程端的真实翻译质量、音色和长视频稳定性必须在应用开通后用公司素材做验收，单元测试不能替代供应商实测。
