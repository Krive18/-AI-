# 原生本地依赖与 Redis 升级门槛设计

## 状态

已确认，2026-09-01。

## 背景

开发电脑已经运行 MySQL 8.0.45，并以免安装方式运行 Redis 3.2.100。Docker Desktop 无法正常启动，且项目不需要部署到运营同事的电脑；运营同事最终只通过浏览器使用集中部署的系统。腾讯云服务器的操作系统、网络和进程编排方案尚未确定，本阶段不提前选择。

## 决策

1. 本地开发不依赖 Docker，也不提供 Docker Compose 作为必需启动方式。
2. 本地数据库基线为 MySQL 8.0.45，使用现有 `MySQL80` Windows 服务。
3. 本地 Redis 3.2.100 仅作为开发兼容实例，连接固定使用 RESP2；它不是受支持的生产基线。
4. 正式环境 Redis 必须升级到 7.2 或更高版本，并在上线计划中重新核对 redis-py、Celery 与服务端版本兼容矩阵。未完成真实 Redis 集成测试、持久化、认证、私网访问和故障恢复验证时不得上线。
5. MySQL 保存账号、任务、费用和审计等业务真相；Redis 只保存会话、限流、锁、队列和短期进度。Redis 故障不得造成永久业务记录丢失。
6. 腾讯云服务器操作系统、部署拓扑和进程管理方式留给后续独立上线计划，本阶段不写入 Linux、Windows、容器或 Nginx 的强制结论。

## 本地连接契约

- MySQL：`127.0.0.1:3306`，服务端版本 8.0.45。
- Redis：`127.0.0.1:6379`，本地开发设置 `REDIS_PROTOCOL=2`。
- `.env.example` 只保存无秘密占位值；真实本地密码只写入被 Git 忽略的 `.env`。
- 仓库检查只验证代码和依赖清单；本地服务检查独立验证 TCP 连通性，避免把机器状态混入可复现的静态检查。

## 验证门槛

- 仓库检查不调用 Docker。
- 本地服务检查能确认 3306 和 6379 可连接，并在端口不可用时返回非零退出码。
- 项目锁定的 redis-py 客户端在 RESP2 下能对本地 Redis 执行 `PING`。
- 上线计划必须把 Redis 7.2+ 兼容性和真实集成测试列为阻断项，不能通过配置开关绕过。

## 影响

- 当前开发可以复用已有 MySQL 和 Redis，不再被 Docker Desktop 阻塞。
- Redis 3.2 的兼容模式只覆盖当前阶段所需的基础命令，不能据此推断生产兼容性。
- 生产部署细节延后，但升级门槛已在规格中固定，后续不能把本地旧版本直接搬到正式环境。
