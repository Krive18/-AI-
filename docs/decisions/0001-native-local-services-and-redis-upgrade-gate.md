# ADR-0001: 使用原生本地服务并设置 Redis 生产升级门槛

## 状态

Accepted

## 日期

2026-09-01

## 背景

Docker Desktop 在当前开发电脑上因 Inference Manager 初始化异常无法启动。电脑已经运行 MySQL 8.0.45 和 Redis 3.2.100，运营同事未来通过浏览器使用集中部署的系统，不需要在个人电脑安装服务端依赖。腾讯云正式环境的操作系统和部署拓扑尚未选择。

## 决策

开发阶段使用现有原生 MySQL 和 Redis，删除 Docker 运行依赖。本地 Redis 通过 RESP2 兼容模式连接，但正式环境必须使用 Redis 7.2 或更高版本，并通过真实集成、认证、持久化和故障恢复验证。正式服务器操作系统与部署方式推迟到独立上线计划决定。

## 备选方案

### 修复并继续使用 Docker Desktop

- 优点：依赖版本隔离和启动方式统一。
- 缺点：当前 Docker 后端无法稳定启动，会持续阻塞开发。
- 结论：拒绝作为当前开发依赖。

### 把 Redis 3.2 作为长期基线

- 优点：无需升级现有本地程序。
- 缺点：不在当前 redis-py 支持矩阵内，默认 RESP3 握手失败，无法满足上线兼容性要求。
- 结论：只允许本地 RESP2 兼容，不允许进入正式环境。

### 现在确定腾讯云服务器操作系统

- 优点：可以提前编写完整部署脚本。
- 缺点：服务器规格和运维条件尚未确定，属于过早决策。
- 结论：推迟到上线计划。

## 后果

- 本地启动说明必须使用原生服务，不再出现 Docker 必需命令。
- 应用配置需要显式支持本地 RESP2。
- 上线检查必须阻止 Redis 3.2 或其他低于 7.2 的版本进入正式环境。
- MySQL 和 Redis 的安装、升级与备份流程在后续上线计划中补充。
