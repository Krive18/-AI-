# 寰语深色霓虹界面升级设计

## 目标

以用户提供的登录页截图与单文件 HTML 为唯一视觉基准，将现有 Vue 3 前端统一升级为“寰语”深色霓虹智能视频全球化工作台。升级覆盖登录页、用户端、管理端与公共状态组件，保留已有路由、业务功能、数据接口和权限逻辑。

## 设计原则

- 所有可见品牌统一为“寰语”，清理旧品牌和现有橙色品牌样式。
- 登录页忠实保留左侧品牌宣传、地球连线视觉和右侧登录卡片，以参考图的字号、间距、比例、边框和发光效果为标准。
- 用户端和管理端延续同一品牌语言，但保持数据密度和信息层级，不套用通用后台模板。
- 发光效果只用于主操作、当前导航、任务进度和健康状态，不让每张卡片都成为高亮光源。
- 所有界面只展示真实 API 数据、真实空状态和真实错误状态，不增加模拟数据。

## 视觉变量

新增独立的 `src/styles/tokens.css`，由 `main.css` 引入。变量按语义命名，禁止页面内重复硬编码主题色。

- 背景：`#050B18`
- 一级表面：`#071126`
- 浮层表面：`#0B1730`
- 霓虹青：`#32B7FF`
- 电光蓝：`#4778FF`
- 智能紫：`#8B52FF`
- 文字采用冷白、亮蓝灰和弱蓝灰三级；成功、警告、危险保留独立语义色。
- 间距以 4px 为基础节奏，建立 4、8、12、16、20、24、32、40、48、64 的可复用尺度。
- 圆角分为控件、卡片、大型面板三级；阴影分为表面层级、主操作霓虹和焦点环三类。
- 中文使用本地系统无衬线字体栈，英文和数据优先 Inter，不依赖境外字体 CDN。

## 前端架构

### 正式 Vue 应用

- `frontend/index.html`：更新页面标题、主题色和站点描述，仍作为 Vite 入口。
- `frontend/src/styles/tokens.css`：品牌、语义色、间距、圆角、阴影、字体和动效变量。
- `frontend/src/styles/main.css`：公共布局、表单、卡片、表格、状态、响应式与无障碍样式。
- `BrandLogo.vue`：统一使用参考稿的气泡翻译品牌标识和“寰语”字标。
- `TranslationGlobe.vue`：将用户提供 HTML 中的地球连线视觉抽成品牌组件，不用占位图或新生成素材替代。
- `LoginView.vue`：负责真实登录交互、密码可见性、字段校验、提交状态和错误反馈。
- `AppSidebar.vue` 与 `AppHeader.vue`：更换为品牌化工作区外壳，保留现有用户端和管理端导航数据。
- 各视图保留现有数据获取和事件处理，通过公共设计类和少量语义容器完成视觉升级。

### 三文件视觉样板

在 `frontend/design-reference/` 保留一份不参与正式应用构建的完整视觉样板：

- `index.html`：语义化的登录页结构。
- `styles.css`：完整设计变量、桌面和移动布局、交互状态与无障碍样式。
- `app.js`：通过页面配置读取 API 基地址，调用真实登录接口，不包含延时器、模拟登录或模拟成功提示。

## 登录数据流

1. 用户输入“账号”和“密码”，字段名保持 `loginName` 与 `password`。
2. Vue 应用继续通过 Pinia `auth.login()` 调用 `POST /api/v1/auth/login`。
3. 请求沿用现有 `apiFetch`、Cookie 会话和 CSRF 管理，不在界面代码中保存密码或密钥。
4. 登录成功后保留现有角色跳转：管理员进入 `/admin`，运营成员进入 `/translations/new`，需更改初始密码的账号进入 `/change-password`。
5. 参考稿中的“邮箱地址”、“企业邮箱”与邮箱格式校验全部改为账号语义。
6. 不提供虚假的“忘记密码”链路；界面明确引导用户联系管理员重置密码。
7. 若保留记忆选项，文案为“记住账号”，仅本地保存账号名，不保存密码或登录凭据。

## 用户端和管理端

### 用户端

- 突出“新建翻译”与“我的记录”两条主路径。
- 上传区使用青蓝焦点态和清晰的文件限制提示；语言选择、交付选项、费用估算继续使用真实数据。
- 记录页和详情页使用连线进度、发光节点和文字标签同时表达任务状态，不仅依赖颜色。

### 管理端

- 保留运行概览、账号管理、翻译任务、接口配置、调用费用和操作日志路由。
- 后台使用更高的信息密度、更弱的面板发光和更清晰的表格边界，但与用户端共享品牌、导航和状态系统。
- 接口健康、费用和日志界面使用真实空状态，不伪造提供商、调用记录或费用数据。

## 响应式与无障碍

- 验证 320px、768px、1024px、1440px 和参考图 1673×941 视口。
- 桌面登录页维持左右两栏；平板和手机改为品牌摘要、登录卡、简化地球的单列顺序。
- 工作区桌面使用固定侧栏，窄屏使用可关闭的导航抽屉。
- 所有表单控件保留可见标签、错误关联和清晰焦点环；图标按钮有可读名称。
- 保证普通正文至少 4.5:1 对比度，大字和控件边界至少 3:1。
- 支持键盘导航、`aria-live` 登录反馈、`prefers-reduced-motion` 和小屏触摸目标。

## 错误和状态

- API 错误继续使用后端稳定错误消息，界面只进行安全、简洁的用户表达。
- 加载、空数据、成功、警告和失败都有明确的文字与图标，不以颜色作为唯一区分。
- 登录提交期间锁定重复提交，失败后恢复控件并保留账号输入。
- 连接真实接口时不在页面输出密码、Cookie、CSRF 令牌或提供商密钥。

## 验证方案

1. 先补充登录界面行为测试，覆盖账号字段、密码显示、真实 `auth.login()` 调用、加载状态和错误反馈。
2. 运行 Vitest、Vue TypeScript 类型检查、ESLint 和 Vite 生产构建。
3. 通过 Codex 内置浏览器检查登录、用户端和管理端主要路径，确认导航、表单、表格、空状态和主操作可用。
4. 在目标视口进行截图对比，检查参考图与登录实现的比例、字号、间距、地球位置、卡片边框和发光差异。
5. 运行 axe 检查并手动验证键盘访问与减少动效。
6. 在项目根目录保存 `design-qa.md`，只在 P0、P1、P2 视觉和可用性问题解决且结果为 `final result: passed` 后交付。

## 非目标

- 不改动 Python 后端、MySQL、Redis、任务执行器和豆包接口逻辑。
- 不新增注册、套餐、支付、找回密码、新业务路由或模拟数据。
- 不更改后端 API 请求与响应契约。

## 交付标准

- 登录页在 1673×941 视口的整体构图与参考图一致，并使用“账号 + 密码”语义。
- 用户端和管理端统一属于“寰语”，同时保持两类用户的导航与信息密度差异。
- 三文件视觉样板可独立打开，其 API 请求地址可配置且不包含模拟登录。
- 现有前端功能、路由和真实数据流不回归，所有自动检查与视觉 QA 通过。
